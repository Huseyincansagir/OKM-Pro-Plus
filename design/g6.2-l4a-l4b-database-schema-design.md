# G6.2 L4-A / L4-B PostgreSQL Veritabanı Şema Tasarımı

**Durum:** Kodlama ve migration öncesi teknik tasarım

**Kapsam:** `L4-A Physical Logistics Master` ile `L4-B LoadPlan + VehicleFit + First Fit Decreasing` bounded slice’larının tablo, ilişki, snapshot, versioning, constraint, index ve migration tasarımı.

**Kapsam dışı:** Load verification, gerçek barkod tarama, departure, GPS/traffic integration, teslim proof, optimal 3D bin-packing, otomatik rota optimizasyonu ve mobil UI.

## 1. Tasarım özeti

L4-A fiziksel planlamanın güvenilir ana verisini üretir. L4-B bu ana veriyi kullanarak bir shipment için `LoadPlan`, `LoadUnit`, `VehicleFitEvaluation` ve validation sonuçlarını oluşturur. LoadPlan ticari miktar veya stok hareketi üretmez; mevcut shipment miktarlarının fiziksel taşıma birimlerine dağılımını saklar [1] [2].

| Bounded slice | Ana tablolar | Çıkış |
|---|---|---|
| L4-A Physical Logistics Master | `product_physical_profiles`, `packaging_physical_profiles`, `pallet_types`, `vehicle_capacity_pallet_types`, `vehicle_capacity_zones` | Version’lanmış fiziksel ana veri |
| L4-A Vehicle Capacity extension | `vehicle_capacities` alan genişletmesi | İç ölçü, kapı, zemin, yükseklik, payload ve palet uyumluluğu |
| L4-B Shipment physical bridge | `shipment_packages` | Barkodlu fiziksel paket, müşteri ve RouteStop bağlantısı |
| L4-B LoadPlan | `load_plans`, `load_plan_versions` yerine version alanı | Shipment’a bağlı öneri, validation, onay ve lock |
| L4-B Candidate fit | `vehicle_fit_evaluations` | Seçilen ve elenen araçların açıklanabilir snapshot’ı |
| L4-B Physical units | `load_units`, `load_unit_items`, `load_unit_stop_allocations` | Palet/kafes/koli grubu dağılımı |
| L4-B Validation/audit | `load_plan_validation_results`, `load_plan_manual_changes` | Hard/soft sonuçlar, resolution, override ve audit |

### 1.1 Uygulanacak ölçü standardı

Şema, isimsiz `length`, `width` veya `weight` alanları yerine açık suffix kullanmalıdır. Önerilen internal standard şöyledir:

| Fiziksel değer | PostgreSQL kolonu | Birim |
|---|---|---|
| Uzunluk, genişlik, yükseklik | `*_mm` | milimetre |
| Net, dara ve brüt ağırlık | `*_kg` | kilogram |
| Hacim | `*_m3` | metreküp |
| Miktar | `quantity_base` | Shipment item’ın base UOM’u |
| Zaman | `timestamptz` | UTC |

Bu seçim, kullanıcı arayüzündeki `cm`, `kg` veya `m³` gösteriminden bağımsızdır. Her fiziksel kayıt için nominal precision `numeric(18,6)` kullanılmalıdır. Birim dönüşümü frontend’e bırakılmamalıdır [1].

## 2. L4-A: ProductPhysicalProfile

`ProductPhysicalProfile`, ürünün temel birimine ait fiziksel ve taşıma kurallarını tutar. Mevcut `products` tablosuna ölçü alanlarını doğrudan eklemek yerine ayrı tablo kullanılması, fiziksel ana verinin effective-date ile yönetilmesini ve ticari ürün modelinden ayrılmasını sağlar.

```sql
CREATE TABLE product_physical_profiles (
    id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    product_id uuid NOT NULL REFERENCES products(id) ON DELETE RESTRICT,
    effective_from timestamptz NOT NULL,
    effective_to timestamptz,

    length_mm numeric(18,6) NOT NULL,
    width_mm numeric(18,6) NOT NULL,
    height_mm numeric(18,6) NOT NULL,
    net_weight_kg numeric(18,6) NOT NULL,
    volume_m3 numeric(18,6),

    is_stackable boolean NOT NULL DEFAULT true,
    max_stack_count integer,
    max_load_above_kg numeric(18,6),
    keep_upright boolean NOT NULL DEFAULT false,
    is_fragile boolean NOT NULL DEFAULT false,
    compatibility_group varchar(80),
    incompatible_groups jsonb NOT NULL DEFAULT '[]'::jsonb,
    allowed_orientations jsonb NOT NULL DEFAULT '["LWH", "WLH"]'::jsonb,
    physical_policy_snapshot jsonb NOT NULL DEFAULT '{}'::jsonb,

    created_at timestamptz NOT NULL DEFAULT now(),
    updated_at timestamptz NOT NULL DEFAULT now(),
    row_version bigint NOT NULL DEFAULT 1,

    CONSTRAINT ck_product_physical_dimensions_positive
        CHECK (length_mm > 0 AND width_mm > 0 AND height_mm > 0),
    CONSTRAINT ck_product_physical_weight_positive
        CHECK (net_weight_kg >= 0),
    CONSTRAINT ck_product_physical_volume_positive
        CHECK (volume_m3 IS NULL OR volume_m3 > 0),
    CONSTRAINT ck_product_physical_effective_range
        CHECK (effective_to IS NULL OR effective_to > effective_from),
    CONSTRAINT ck_product_physical_stack_rules
        CHECK (max_stack_count IS NULL OR max_stack_count >= 1),
    CONSTRAINT ck_product_physical_load_above
        CHECK (max_load_above_kg IS NULL OR max_load_above_kg >= 0),
    CONSTRAINT uq_product_physical_effective_start
        UNIQUE (product_id, effective_from)
);

CREATE INDEX ix_product_physical_active_lookup
    ON product_physical_profiles (product_id, effective_from DESC)
    WHERE effective_to IS NULL;
```

Bir ürün için aynı effective period’un çakışmaması application command ile kontrol edilmelidir. PostgreSQL’de tarih aralıklarının overlap’ini database seviyesinde de korumak için `tstzrange` generated expression ve GiST exclusion constraint eklenebilir; mevcut EF Core modelinin bunu desteklemediği durumda migration SQL’inde açıkça uygulanmalı veya transaction-level guard kullanılmalıdır.

Önerilen fiziksel profil sorgusu:

```sql
SELECT p.*
FROM product_physical_profiles p
WHERE p.product_id = :product_id
  AND p.effective_from <= :as_of
  AND (p.effective_to IS NULL OR :as_of < p.effective_to)
ORDER BY p.effective_from DESC
LIMIT 1;
```

Aynı sorgu sıfır veya birden fazla kayıt döndürürse planlama `PHYSICAL_PROFILE_MISSING` ya da `PHYSICAL_PROFILE_AMBIGUOUS` ile durmalıdır.

## 3. L4-A: PackagingPhysicalProfile

Mevcut `product_packagings` tablosu miktar dönüşümünü (`quantity_in_base_uom`) yönetir; dış ölçü ve taşıma davranışını doğrudan aynı tabloya koymak yerine `packaging_physical_profiles` bu bilgiyi taşır. Böylece “5 koli”nin ticari miktarı ile fiziksel yük davranışı ayrılır [1].

```sql
CREATE TABLE packaging_physical_profiles (
    id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    packaging_id uuid NOT NULL REFERENCES product_packagings(id) ON DELETE RESTRICT,
    effective_from timestamptz NOT NULL,
    effective_to timestamptz,

    units_per_package numeric(18,6) NOT NULL,
    length_mm numeric(18,6) NOT NULL,
    width_mm numeric(18,6) NOT NULL,
    height_mm numeric(18,6) NOT NULL,
    net_weight_kg numeric(18,6),
    tare_weight_kg numeric(18,6) NOT NULL DEFAULT 0,
    gross_weight_kg numeric(18,6),
    volume_m3 numeric(18,6),

    is_stackable boolean NOT NULL DEFAULT true,
    max_stack_count integer,
    max_load_above_kg numeric(18,6),
    keep_upright boolean NOT NULL DEFAULT false,
    is_fragile boolean NOT NULL DEFAULT false,
    compatibility_group varchar(80),
    incompatible_groups jsonb NOT NULL DEFAULT '[]'::jsonb,
    allowed_orientations jsonb NOT NULL DEFAULT '["LWH", "WLH"]'::jsonb,
    physical_policy_snapshot jsonb NOT NULL DEFAULT '{}'::jsonb,

    created_at timestamptz NOT NULL DEFAULT now(),
    updated_at timestamptz NOT NULL DEFAULT now(),
    row_version bigint NOT NULL DEFAULT 1,

    CONSTRAINT ck_packaging_physical_units_positive
        CHECK (units_per_package > 0),
    CONSTRAINT ck_packaging_physical_dimensions_positive
        CHECK (length_mm > 0 AND width_mm > 0 AND height_mm > 0),
    CONSTRAINT ck_packaging_physical_weights_nonnegative
        CHECK (
            (net_weight_kg IS NULL OR net_weight_kg >= 0)
            AND tare_weight_kg >= 0
            AND (gross_weight_kg IS NULL OR gross_weight_kg >= 0)
        ),
    CONSTRAINT ck_packaging_physical_gross_consistent
        CHECK (
            gross_weight_kg IS NULL
            OR net_weight_kg IS NULL
            OR gross_weight_kg >= net_weight_kg + tare_weight_kg
        ),
    CONSTRAINT ck_packaging_physical_effective_range
        CHECK (effective_to IS NULL OR effective_to > effective_from),
    CONSTRAINT ck_packaging_physical_stack_rules
        CHECK (max_stack_count IS NULL OR max_stack_count >= 1),
    CONSTRAINT uq_packaging_physical_effective_start
        UNIQUE (packaging_id, effective_from)
);

CREATE INDEX ix_packaging_physical_active_lookup
    ON packaging_physical_profiles (packaging_id, effective_from DESC)
    WHERE effective_to IS NULL;
```

`net_weight_kg`, `gross_weight_kg` ve `volume_m3` aynı anda hem ürün hem ambalajdan iki kez hesaplanmamalıdır. Bu nedenle `physical_policy_snapshot` içinde `weight_source` ve `volume_source` değerleri örneğin `Product`, `Packaging` veya `Derived` olarak saklanmalıdır.

## 4. L4-A: PalletType

`PalletType`, fiziksel bir ürün kartı değildir; LoadPlan içinde bir LoadUnit’in taşıyıcı profilidir. Aynı palet tipi farklı shipment’larda kullanılabilir, ancak plan oluşturulduğunda kullanılan profile LoadUnit’e snapshot olarak yazılmalıdır.

```sql
CREATE TABLE pallet_types (
    id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    code varchar(80) NOT NULL UNIQUE,
    name varchar(160) NOT NULL,
    length_mm numeric(18,6) NOT NULL,
    width_mm numeric(18,6) NOT NULL,
    height_mm numeric(18,6) NOT NULL,
    tare_weight_kg numeric(18,6) NOT NULL DEFAULT 0,
    max_gross_weight_kg numeric(18,6),
    max_payload_kg numeric(18,6),
    max_load_height_mm numeric(18,6),
    max_stack_count integer,
    is_stackable boolean NOT NULL DEFAULT false,
    is_active boolean NOT NULL DEFAULT true,
    policy_snapshot jsonb NOT NULL DEFAULT '{}'::jsonb,
    created_at timestamptz NOT NULL DEFAULT now(),
    updated_at timestamptz NOT NULL DEFAULT now(),
    row_version bigint NOT NULL DEFAULT 1,

    CONSTRAINT ck_pallet_dimensions_positive
        CHECK (length_mm > 0 AND width_mm > 0 AND height_mm > 0),
    CONSTRAINT ck_pallet_weights_nonnegative
        CHECK (
            tare_weight_kg >= 0
            AND (max_gross_weight_kg IS NULL OR max_gross_weight_kg >= 0)
            AND (max_payload_kg IS NULL OR max_payload_kg >= 0)
        ),
    CONSTRAINT ck_pallet_payload_not_over_gross
        CHECK (
            max_payload_kg IS NULL
            OR max_gross_weight_kg IS NULL
            OR max_payload_kg <= max_gross_weight_kg
        ),
    CONSTRAINT ck_pallet_stack_rules
        CHECK (max_stack_count IS NULL OR max_stack_count >= 1)
);
```

`max_payload_kg` doluysa taşıma kapasitesinin source of truth’u odur; boşsa `max_gross_weight_kg - tare_weight_kg` hesaplanabilir. Hesaplanmış değer plan snapshot’ına açıkça yazılmalıdır.

## 5. L4-A: VehicleCapacity fiziksel extension

Mevcut `vehicle_capacities` tablosu versioned effective profile olarak korunmalıdır. L4-A yeni ana tablo oluşturmak yerine bu tabloyu fiziksel alanlarla genişletmelidir. Böylece mevcut `VehicleType → VehicleCapacity → Vehicle` ilişkisi bozulmaz.

```sql
ALTER TABLE vehicle_capacities
    ADD COLUMN inner_length_mm numeric(18,6),
    ADD COLUMN inner_width_mm numeric(18,6),
    ADD COLUMN inner_height_mm numeric(18,6),
    ADD COLUMN door_width_mm numeric(18,6),
    ADD COLUMN door_height_mm numeric(18,6),
    ADD COLUMN floor_length_mm numeric(18,6),
    ADD COLUMN floor_width_mm numeric(18,6),
    ADD COLUMN floor_load_limit_kg numeric(18,6),
    ADD COLUMN max_usable_volume_m3 numeric(18,6),
    ADD COLUMN max_payload_kg numeric(18,6),
    ADD COLUMN max_load_height_mm numeric(18,6),
    ADD COLUMN max_stack_count integer,
    ADD COLUMN loading_sides jsonb NOT NULL DEFAULT '["Rear"]'::jsonb,
    ADD COLUMN unloading_sides jsonb NOT NULL DEFAULT '["Rear"]'::jsonb,
    ADD COLUMN allowed_orientations jsonb NOT NULL DEFAULT '["LWH", "WLH"]'::jsonb,
    ADD COLUMN physical_policy_snapshot jsonb NOT NULL DEFAULT '{}'::jsonb,
    ADD COLUMN row_version bigint NOT NULL DEFAULT 1;

ALTER TABLE vehicle_capacities
    ADD CONSTRAINT ck_vehicle_capacity_physical_dimensions
    CHECK (
        inner_length_mm IS NULL OR inner_length_mm > 0
    ) NOT VALID;

ALTER TABLE vehicle_capacities
    ADD CONSTRAINT ck_vehicle_capacity_payload
    CHECK (
        max_payload_kg IS NULL OR max_payload_kg >= 0
    ) NOT VALID;

CREATE TABLE vehicle_capacity_pallet_types (
    vehicle_capacity_id uuid NOT NULL
        REFERENCES vehicle_capacities(id) ON DELETE RESTRICT,
    pallet_type_id uuid NOT NULL
        REFERENCES pallet_types(id) ON DELETE RESTRICT,
    PRIMARY KEY (vehicle_capacity_id, pallet_type_id)
);

CREATE TABLE vehicle_capacity_zones (
    id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    vehicle_capacity_id uuid NOT NULL
        REFERENCES vehicle_capacities(id) ON DELETE RESTRICT,
    zone_code varchar(80) NOT NULL,
    length_mm numeric(18,6) NOT NULL,
    width_mm numeric(18,6) NOT NULL,
    max_load_kg numeric(18,6),
    access_side varchar(30),
    sequence_no integer NOT NULL,
    UNIQUE (vehicle_capacity_id, zone_code),
    UNIQUE (vehicle_capacity_id, sequence_no),
    CHECK (length_mm > 0 AND width_mm > 0),
    CHECK (max_load_kg IS NULL OR max_load_kg >= 0),
    CHECK (sequence_no >= 1)
);

CREATE INDEX ix_vehicle_capacity_effective_lookup
    ON vehicle_capacities (vehicle_type_id, effective_from DESC);

CREATE INDEX ix_vehicle_capacity_pallet_type_lookup
    ON vehicle_capacity_pallet_types (pallet_type_id, vehicle_capacity_id);
```

`NOT VALID` constraint yaklaşımı yalnızca mevcut migration’da eski capacity satırları boş kalacaksa kullanılmalıdır. L4-A release migration’ı tamamlanmadan önce fiziksel alanları nullable bırakmak sadece seed/backfill döneminde kabul edilmelidir. Yeni veya lock’a girecek capacity profile için tüm hard-fit alanları zorunlu olmalıdır.

## 6. L4-B: ShipmentPackage

`shipment_packages` shipment içindeki barkodlu fiziksel birimleri temsil eder. Package, müşteri ve `RouteStop` bağlantısı olmadan LoadPlan lock edilemez [2]. Mevcut canonical şema korunmalı; aşağıdaki alanlarla güçlendirilmelidir:

```sql
ALTER TABLE shipment_packages
    ADD COLUMN row_version bigint NOT NULL DEFAULT 1,
    ADD COLUMN customer_id uuid REFERENCES customers(id) ON DELETE RESTRICT,
    ADD COLUMN packaging_snapshot jsonb NOT NULL DEFAULT '{}'::jsonb;

ALTER TABLE shipment_packages
    ADD CONSTRAINT ck_shipment_package_status
    CHECK (status IN ('Planned', 'Assigned', 'Loaded', 'InTransit', 'Delivered', 'Exception'));

CREATE INDEX ix_shipment_packages_stop_status
    ON shipment_packages (route_stop_id, status);

CREATE INDEX ix_shipment_packages_shipment_status
    ON shipment_packages (shipment_id, status);
```

`customer_id` shipment item veya route stop’tan türetilebiliyorsa command tarafında eşitlik doğrulanmalıdır. Aksi halde package’ın başka müşterinin stop’una bağlanması yalnızca FK’lerle engellenemez.

## 7. L4-B: LoadPlan

```sql
CREATE TABLE load_plans (
    id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    shipment_id uuid NOT NULL REFERENCES shipments(id) ON DELETE RESTRICT,
    route_plan_id uuid NOT NULL REFERENCES route_plans(id) ON DELETE RESTRICT,
    route_plan_version integer NOT NULL,
    vehicle_id uuid REFERENCES vehicles(id) ON DELETE RESTRICT,
    vehicle_capacity_id uuid REFERENCES vehicle_capacities(id) ON DELETE RESTRICT,

    status varchar(30) NOT NULL DEFAULT 'Draft',
    version integer NOT NULL DEFAULT 1,
    replanned_from_id uuid REFERENCES load_plans(id) ON DELETE RESTRICT,

    algorithm_name varchar(120),
    algorithm_version varchar(80),
    parameter_set varchar(120),
    feasibility_status varchar(30),
    fit_score numeric(9,4),
    total_weight_kg numeric(18,6),
    total_volume_m3 numeric(18,6),
    pallet_count integer,
    utilization_snapshot jsonb NOT NULL DEFAULT '{}'::jsonb,
    capacity_snapshot jsonb NOT NULL DEFAULT '{}'::jsonb,
    input_snapshot_hash varchar(128),
    validation_summary jsonb NOT NULL DEFAULT '{}'::jsonb,

    approved_by uuid REFERENCES users(id) ON DELETE RESTRICT,
    approved_at timestamptz,
    locked_at timestamptz,
    locked_by uuid REFERENCES users(id) ON DELETE RESTRICT,
    created_at timestamptz NOT NULL DEFAULT now(),
    updated_at timestamptz NOT NULL DEFAULT now(),
    row_version bigint NOT NULL DEFAULT 1,

    CONSTRAINT uq_load_plan_shipment_version
        UNIQUE (shipment_id, version),
    CONSTRAINT ck_load_plan_status
        CHECK (status IN ('Draft', 'CandidateSelection', 'Proposed', 'Validating', 'Valid', 'NeedsReview', 'Locked', 'Superseded')),
    CONSTRAINT ck_load_plan_feasibility
        CHECK (feasibility_status IS NULL OR feasibility_status IN ('Infeasible', 'FeasibleWithWarnings', 'Feasible')),
    CONSTRAINT ck_load_plan_version_positive
        CHECK (version >= 1),
    CONSTRAINT ck_load_plan_route_version_positive
        CHECK (route_plan_version >= 1),
    CONSTRAINT ck_load_plan_locked_fields
        CHECK ((locked_at IS NULL AND locked_by IS NULL) OR (locked_at IS NOT NULL AND locked_by IS NOT NULL)),
    CONSTRAINT ck_load_plan_approval_fields
        CHECK ((approved_at IS NULL AND approved_by IS NULL) OR (approved_at IS NOT NULL AND approved_by IS NOT NULL)),
    CONSTRAINT ck_load_plan_totals_nonnegative
        CHECK (
            (total_weight_kg IS NULL OR total_weight_kg >= 0)
            AND (total_volume_m3 IS NULL OR total_volume_m3 >= 0)
            AND (pallet_count IS NULL OR pallet_count >= 0)
        )
);

CREATE UNIQUE INDEX ux_load_plan_current_per_shipment
    ON load_plans (shipment_id)
    WHERE status <> 'Superseded';

CREATE INDEX ix_load_plan_route_lookup
    ON load_plans (route_plan_id, route_plan_version);

CREATE INDEX ix_load_plan_vehicle_capacity_lookup
    ON load_plans (vehicle_id, vehicle_capacity_id)
    WHERE status <> 'Superseded';

CREATE INDEX ix_load_plan_status_board
    ON load_plans (status, updated_at DESC);
```

`ux_load_plan_current_per_shipment` ancak uygulama kuralı bir shipment için aynı anda yalnızca bir current plan’a izin veriyorsa kullanılmalıdır. Birden fazla draft plan karşılaştırması MVP’de desteklenecekse bu index oluşturulmamalı; bunun yerine `is_current` boolean veya explicit plan selection alanı kullanılmalıdır. Önerilen MVP kararı tek current plan’dır.

### 7.1 Snapshot kuralları

`capacity_snapshot`, `utilization_snapshot`, `validation_summary`, `input_snapshot_hash` ve `parameter_set` planın üretildiği bağlamı immutable biçimde saklar. Effective capacity veya fiziksel profile sonradan değiştiğinde eski LoadPlan’ın hesapları değişmez. Yeni profile veya route version için yeni LoadPlan version oluşturulur.

`input_snapshot_hash` hesaplaması sıralı canonical JSON üzerinden yapılmalıdır:

```text
shipment items
+ package/stop assignments
+ physical profile ids and effective_from
+ pallet type ids and values
+ vehicle capacity id and values
+ route plan id/version and stop sequence
+ algorithm version
+ parameter set
```

## 8. L4-B: VehicleFitEvaluation

```sql
CREATE TABLE vehicle_fit_evaluations (
    id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    load_plan_id uuid NOT NULL REFERENCES load_plans(id) ON DELETE RESTRICT,
    vehicle_id uuid NOT NULL REFERENCES vehicles(id) ON DELETE RESTRICT,
    vehicle_capacity_id uuid NOT NULL REFERENCES vehicle_capacities(id) ON DELETE RESTRICT,

    candidate_status varchar(30) NOT NULL DEFAULT 'Candidate',
    rejection_code varchar(80),
    fit_score numeric(9,4),
    weight_ratio numeric(9,6),
    volume_ratio numeric(9,6),
    pallet_ratio numeric(9,6),
    floor_area_ratio numeric(9,6),
    height_ratio numeric(9,6),
    door_check_status varchar(30),
    dimension_check_status varchar(30),
    stacking_check_status varchar(30),
    axle_check_status varchar(30),
    stop_access_status varchar(30),
    reason_text text,
    algorithm_name varchar(120) NOT NULL,
    algorithm_version varchar(80) NOT NULL,
    parameter_set varchar(120),
    evaluated_at timestamptz NOT NULL DEFAULT now(),
    input_snapshot_hash varchar(128) NOT NULL,

    CONSTRAINT uq_fit_evaluation_candidate
        UNIQUE (load_plan_id, vehicle_id, vehicle_capacity_id, input_snapshot_hash),
    CONSTRAINT ck_fit_candidate_status
        CHECK (candidate_status IN ('Candidate', 'Recommended', 'Rejected', 'NeedsReview')),
    CONSTRAINT ck_fit_ratios_nonnegative
        CHECK (
            (weight_ratio IS NULL OR weight_ratio >= 0)
            AND (volume_ratio IS NULL OR volume_ratio >= 0)
            AND (pallet_ratio IS NULL OR pallet_ratio >= 0)
            AND (floor_area_ratio IS NULL OR floor_area_ratio >= 0)
            AND (height_ratio IS NULL OR height_ratio >= 0)
        )
);

CREATE INDEX ix_fit_evaluation_plan_status
    ON vehicle_fit_evaluations (load_plan_id, candidate_status, fit_score DESC);

CREATE INDEX ix_fit_evaluation_vehicle_schedule
    ON vehicle_fit_evaluations (vehicle_id, evaluated_at DESC);
```

Elenen araçlar için `rejection_code` zorunlu olmalıdır. PostgreSQL `CHECK` ile status/rejection ilişkisi şöyle korunabilir:

```sql
ALTER TABLE vehicle_fit_evaluations
ADD CONSTRAINT ck_fit_rejection_consistency
CHECK (
    (candidate_status = 'Rejected' AND rejection_code IS NOT NULL)
    OR candidate_status <> 'Rejected'
);
```

## 9. L4-B: LoadUnit ve LoadUnitItem

```sql
CREATE TABLE load_units (
    id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    load_plan_id uuid NOT NULL REFERENCES load_plans(id) ON DELETE RESTRICT,
    pallet_type_id uuid REFERENCES pallet_types(id) ON DELETE RESTRICT,
    unit_code varchar(160) NOT NULL,
    unit_type varchar(30) NOT NULL,
    is_mixed boolean NOT NULL DEFAULT false,

    length_mm numeric(18,6),
    width_mm numeric(18,6),
    height_mm numeric(18,6),
    tare_weight_kg numeric(18,6) NOT NULL DEFAULT 0,
    gross_weight_kg numeric(18,6) NOT NULL DEFAULT 0,
    volume_m3 numeric(18,6) NOT NULL DEFAULT 0,
    stackable boolean NOT NULL DEFAULT false,
    max_stack_count integer,
    placement_zone varchar(80),
    unloading_priority integer,
    status varchar(30) NOT NULL DEFAULT 'Planned',
    row_version bigint NOT NULL DEFAULT 1,

    CONSTRAINT uq_load_unit_code
        UNIQUE (load_plan_id, unit_code),
    CONSTRAINT ck_load_unit_type
        CHECK (unit_type IN ('Pallet', 'Cage', 'CartonGroup', 'Loose')),
    CONSTRAINT ck_load_unit_status
        CHECK (status IN ('Planned', 'Validated', 'Locked', 'Loaded', 'Exception')),
    CONSTRAINT ck_load_unit_dimensions
        CHECK (
            (length_mm IS NULL OR length_mm > 0)
            AND (width_mm IS NULL OR width_mm > 0)
            AND (height_mm IS NULL OR height_mm > 0)
        ),
    CONSTRAINT ck_load_unit_values_nonnegative
        CHECK (tare_weight_kg >= 0 AND gross_weight_kg >= 0 AND volume_m3 >= 0),
    CONSTRAINT ck_load_unit_stack_rules
        CHECK (max_stack_count IS NULL OR max_stack_count >= 1),
    CONSTRAINT ck_load_unit_priority
        CHECK (unloading_priority IS NULL OR unloading_priority >= 1)
);

CREATE INDEX ix_load_unit_plan_status
    ON load_units (load_plan_id, status);

CREATE TABLE load_unit_items (
    id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    load_unit_id uuid NOT NULL REFERENCES load_units(id) ON DELETE RESTRICT,
    shipment_item_id uuid NOT NULL REFERENCES shipment_items(id) ON DELETE RESTRICT,
    product_id uuid NOT NULL REFERENCES products(id) ON DELETE RESTRICT,
    packaging_id uuid REFERENCES product_packagings(id) ON DELETE RESTRICT,
    physical_profile_id uuid REFERENCES product_physical_profiles(id) ON DELETE RESTRICT,
    packaging_physical_profile_id uuid REFERENCES packaging_physical_profiles(id) ON DELETE RESTRICT,

    entered_quantity numeric(18,6),
    quantity_base numeric(18,6) NOT NULL,
    net_weight_kg numeric(18,6),
    packaging_tare_kg numeric(18,6),
    gross_weight_kg numeric(18,6),
    volume_m3 numeric(18,6),
    compatibility_snapshot jsonb NOT NULL DEFAULT '{}'::jsonb,
    packaging_snapshot jsonb NOT NULL,
    stack_level integer,
    orientation varchar(30),
    row_version bigint NOT NULL DEFAULT 1,

    CONSTRAINT ck_load_unit_item_quantity
        CHECK (quantity_base > 0),
    CONSTRAINT ck_load_unit_item_values_nonnegative
        CHECK (
            (net_weight_kg IS NULL OR net_weight_kg >= 0)
            AND (packaging_tare_kg IS NULL OR packaging_tare_kg >= 0)
            AND (gross_weight_kg IS NULL OR gross_weight_kg >= 0)
            AND (volume_m3 IS NULL OR volume_m3 >= 0)
        ),
    CONSTRAINT ck_load_unit_item_stack_level
        CHECK (stack_level IS NULL OR stack_level >= 1)
);

CREATE INDEX ix_load_unit_item_shipment_item
    ON load_unit_items (shipment_item_id, load_unit_id);

CREATE INDEX ix_load_unit_item_unit
    ON load_unit_items (load_unit_id);
```

`load_unit_items` üzerinde `(load_unit_id, shipment_item_id)` unique olmamalıdır; bir item farklı physical profile veya package split nedeniyle birden fazla allocation satırına bölünebilir. Miktar tavanı `SUM(quantity_base) <= shipment_items.quantity_base` şeklinde olduğundan sıradan `CHECK` ile enforce edilemez. Application transaction ve aşağıdaki gibi deferred constraint trigger birlikte önerilir:

```sql
-- İllustrative design; implementation migration’ında trigger function olarak kodlanmalıdır.
-- Trigger, ilgili shipment_item_id için load_plan version toplamını yeniden hesaplar
-- ve shipment_items.quantity_base üstünü aşarsa exception fırlatır.
```

## 10. L4-B: LoadUnitStopAllocation

Route stop sahipliğinin yalnızca ayrı FK’lerle korunması yeterli değildir; bir `route_stop_id` başka route plan’a ait olabilir. Bu nedenle önerilen şema `load_plans.route_plan_id` ve `route_plan_version` alanlarını zorunlu tutar ve allocation command’inde route ownership tekrar doğrulanır.

```sql
CREATE TABLE load_unit_stop_allocations (
    id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    load_unit_item_id uuid NOT NULL REFERENCES load_unit_items(id) ON DELETE RESTRICT,
    route_stop_id uuid NOT NULL REFERENCES route_stops(id) ON DELETE RESTRICT,
    shipment_package_id uuid REFERENCES shipment_packages(id) ON DELETE RESTRICT,
    quantity_base numeric(18,6) NOT NULL,
    package_count integer,
    unloading_sequence integer,
    access_priority integer,

    CONSTRAINT ck_stop_allocation_quantity
        CHECK (quantity_base > 0),
    CONSTRAINT ck_stop_allocation_package_count
        CHECK (package_count IS NULL OR package_count > 0),
    CONSTRAINT ck_stop_allocation_sequence
        CHECK (unloading_sequence IS NULL OR unloading_sequence >= 1),
    CONSTRAINT ck_stop_allocation_priority
        CHECK (access_priority IS NULL OR access_priority >= 1)
);

CREATE INDEX ix_stop_allocation_stop
    ON load_unit_stop_allocations (route_stop_id, unloading_sequence);

CREATE INDEX ix_stop_allocation_package
    ON load_unit_stop_allocations (shipment_package_id)
    WHERE shipment_package_id IS NOT NULL;
```

Aynı `shipment_package_id` iki aktif LoadUnit allocation’a bağlanamamalıdır. Package bölünebilirliği desteklenirse unique index doğrudan package üzerinde değil, package allocation status/version modeline göre tasarlanmalıdır. MVP’de package’ın tek aktif LoadUnit allocation’ı olması önerilir:

```sql
CREATE UNIQUE INDEX ux_active_package_load_unit
    ON load_unit_stop_allocations (shipment_package_id)
    WHERE shipment_package_id IS NOT NULL;
```

Bu index yalnızca paket bölme desteği MVP dışında bırakılıyorsa uygundur. Paket bölme daha sonra desteklenirse `allocated_quantity_base` ve allocation state gerekir.

## 11. Validation ve manual change tabloları

```sql
CREATE TABLE load_plan_validation_results (
    id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    load_plan_id uuid NOT NULL REFERENCES load_plans(id) ON DELETE RESTRICT,
    severity varchar(20) NOT NULL,
    rule_code varchar(80) NOT NULL,
    entity_type varchar(120),
    entity_id uuid,
    message text NOT NULL,
    suggested_action text,
    is_resolved boolean NOT NULL DEFAULT false,
    resolved_by uuid REFERENCES users(id) ON DELETE RESTRICT,
    resolved_at timestamptz,
    resolution_action varchar(30),
    resolution_reason text,
    created_at timestamptz NOT NULL DEFAULT now(),

    CONSTRAINT ck_validation_severity
        CHECK (severity IN ('HardError', 'Warning', 'Info')),
    CONSTRAINT ck_validation_resolution_fields
        CHECK (
            (is_resolved = false AND resolved_by IS NULL AND resolved_at IS NULL)
            OR (is_resolved = true AND resolved_by IS NOT NULL AND resolved_at IS NOT NULL)
        )
);

CREATE INDEX ix_validation_plan_open
    ON load_plan_validation_results (load_plan_id, severity, rule_code)
    WHERE is_resolved = false;

CREATE TABLE load_plan_manual_changes (
    id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    load_plan_id uuid NOT NULL REFERENCES load_plans(id) ON DELETE RESTRICT,
    entity_type varchar(120) NOT NULL,
    entity_id uuid,
    previous_value jsonb NOT NULL,
    new_value jsonb NOT NULL,
    reason text NOT NULL,
    changed_by uuid NOT NULL REFERENCES users(id) ON DELETE RESTRICT,
    changed_at timestamptz NOT NULL DEFAULT now(),

    CONSTRAINT ck_manual_change_reason_nonempty
        CHECK (length(btrim(reason)) >= 3)
);

CREATE INDEX ix_manual_change_plan_time
    ON load_plan_manual_changes (load_plan_id, changed_at DESC);
```

Validation sonucu yeni validation command’iyle yeniden üretildiğinde eski kayıtlar fiziksel olarak silinmemelidir. İki yaklaşım vardır: immutable validation batch tablosu eklemek veya mevcut sonuçları `superseded_at` ile tarihçelemek. MVP’de `load_plan_version` değiştiğinde eski LoadPlan zaten değişmediği için her version’ın validation sonucu ayrı tutulabilir.

## 13. Foreign key ve silme politikası

Lojistik planlama kayıtları operasyonel ve denetlenebilir olduğundan `ON DELETE CASCADE` kullanılmamalıdır. Ürün, ambalaj, araç, kapasite, palet, shipment, route ve user referansları `ON DELETE RESTRICT` olmalıdır.

| Nesne | Silme davranışı | Gerekçe |
|---|---|---|
| Physical profile | Hard delete yerine yeni version/inactive | Eski snapshot korunmalı |
| VehicleCapacity | `RESTRICT` | VehicleFit ve LoadPlan history bozulmamalı |
| PalletType | `RESTRICT` | LoadUnit snapshot referansı |
| ShipmentPackage | `RESTRICT` | LoadUnit/package audit korunmalı |
| LoadPlan | Hard delete yok; `Superseded` | Replan zinciri ve audit |
| LoadUnit | `RESTRICT` | Locked plan history |
| Validation result | Hard delete yok | Approval/rejection kanıtı |
| Manual change | Hard delete yok | Yetkili override audit’i |

## 14. Constraint ve application-level invariant ayrımı

PostgreSQL, tek satırlı kuralları `CHECK`, `UNIQUE` ve FK ile doğrudan koruyabilir. Satır toplamlarını veya başka aggregate sahipliğini kontrol eden kurallar command transaction’ı ve gerekirse deferred trigger gerektirir.

| Kural | Database | Application transaction |
|---|---|---|
| Pozitif fiziksel ölçü | `CHECK` | DTO validation |
| Effective range başlangıç uniqueness | `UNIQUE` | Overlap guard |
| Shipment/version uniqueness | `UNIQUE` | Replan command |
| Unit code uniqueness | `UNIQUE` | Deterministic code generator |
| Package barcode uniqueness | `UNIQUE` | Barcode normalization |
| Quantity allocation ceiling | Deferred trigger veya service lock | Zorunlu |
| Package/customer/stop ownership | Composite FK veya service validation | Zorunlu |
| Hard error yokken lock | Uygulanamaz | `LoadPlan FOR UPDATE` command |
| Warning resolution/override | User FK + fields | Permission + audit |
| Capacity snapshot güncelliği | Snapshot columns | ETag/revalidation |

## 15. Migration sırası

Migration’lar tek büyük ve geri alınması zor bir değişiklik yerine aşağıdaki sırayla uygulanmalıdır:

| Migration | İçerik | Gate |
|---:|---|---|
| M1 | Ölçü standardı, physical profile tabloları ve PalletType | Unit + model |
| M2 | VehicleCapacity fiziksel extension, pallet join ve zone tabloları | Existing seed backfill |
| M3 | ShipmentPackage alanları, status/index ve package-stop validation | Integration |
| M4 | LoadPlan ve VehicleFitEvaluation tabloları | Model + API contract |
| M5 | LoadUnit, LoadUnitItem ve stop allocations | Quantity/ownership tests |
| M6 | Validation result ve manual change tabloları | Approval/security tests |
| M7 | Exclusion/partial indexes/deferred triggers | Concurrency tests |
| M8 | Backfill verification ve NOT NULL hardening | Full migration gate |

M1–M2 aşamasında eski kayıtlar için nullable physical alanlar ve backfill ihtiyacı olabilir. M8’den sonra lock’a girecek yeni capacity profile ve planning item için fiziksel alanlar zorunlu hale getirilmelidir. Migration uygulanmadan önce mevcut `vehicle_capacities`, `product_packagings` ve shipment seed’leri üzerinde backfill raporu alınmalıdır.

## 16. Acceptance test matrisi

| Test grubu | Minimum kontrol |
|---|---|
| Physical profile | Effective profile lookup, overlap rejection, positive dimensions, inactive profile |
| Packaging profile | Net/tare/gross consistency, unit conversion snapshot |
| PalletType | Payload ≤ gross, dimension and stack rules |
| VehicleCapacity | Physical extension, allowed pallet type, zone uniqueness |
| LoadPlan | Shipment/version uniqueness, status guard, locked fields |
| Quantity | `SUM(load_unit_items.quantity_base)` shipment item ceiling |
| Package | Barcode uniqueness, customer/stop ownership, duplicate assignment |
| Candidate | Rejected candidate code and ratio persistence |
| Snapshot | Capacity/profile changes do not mutate locked plan values |
| Validation | HardError blocks lock; warning needs resolution/override |
| Replan | Old plan immutable; new version and `replanned_from_id` |
| Concurrency | Two lock commands yield one winner; stale row version rejected |
| Deletion | Referenced physical/profile/load history cannot be deleted |
| Security | Real login permission, read-only denial, override permission and audit |

## 17. Implementation öncesi netleştirilmesi gereken kararlar

1. Internal volume unit olarak `m³` veya `mm³` seçimi karar log’una eklenmelidir. Bu doküman `m³` seçimini kullanır.
2. MVP’de shipment başına tek current LoadPlan kabul edilmelidir; aksi halde `ux_load_plan_current_per_shipment` kullanılmamalıdır.
3. Package bölme MVP kapsamında değilse `ux_active_package_load_unit` uygulanmalıdır.
4. Physical profile değişiklikleri effective-dated mi yoksa yalnızca snapshot mı olacak netleştirilmelidir; bu doküman ikisini birlikte önerir.
5. RouteStop ownership composite FK ile mi yoksa application transaction guard ile mi korunacağı migration öncesi kesinleştirilmelidir.
6. Quantity ceiling için deferred trigger kullanılıp kullanılmayacağı architecture gate’inde karara bağlanmalıdır. Uygulama yazma yüzeyleri tek bir command service ise row lock + transaction yeterli olabilir; doğrudan SQL writer varsa trigger zorunlu hale gelir.
